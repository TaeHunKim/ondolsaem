# Roadmap

Open work for OndolSaem, roughly in priority order. Done items move to the release notes in the commit history.

## Planned

1. **More models per category.** Most categories offer one usable model today (`ModelCatalog`: OCR has only ML Kit, speech only SenseVoice, faces only SFace; MobileCLIP2-S0, Moonshine and PP-OCRv5 are listed as *Coming soon*). Add curated alternatives per category, each with a license check (`THIRD_PARTY_NOTICES.md`), a SHA-256, measured size and memory, and a runtime that fits (LiteRT-LM, ML Kit, or ONNX through sherpa-onnx's ONNX Runtime and the JNI bridge, see [architecture.md](architecture.md#faces)). Candidates: MobileCLIP2-S0 (embedding, small, English only), Moonshine tiny (speech), PP-OCRv5 mobile (OCR), YuNet as an alternative face detector, smaller or larger chat models.
2. **Default embedding model with audio.** The default is EmbeddingGemma 2 440M (`eg2-440m`, text + images). Nunsori, the first client, also indexes voice recordings and video sound, which only the 740M model (`eg2-740m`) can embed, so 740M is the more natural default. To weigh: download size (+100 MB) and memory, speed of indexing on mid-range phones, and that changing the default re-indexes clients that never chose a model (`ChangeImpact.REINDEX_REQUIRED`; only apply it to new installs, keep the stored choice of existing ones).
3. **First-run screens (onboarding).** A new user opens OndolSaem without knowing what to download. A short wizard: what OndolSaem is (models shared by your apps, nothing leaves the phone), which apps already use it and what they need (from the categories they asked for), a recommended set of models with total size and a Wi-Fi hint, notification permission (downloads, keep-alive), and an optional step for battery optimization when a category is set to keep loaded.
4. **Real-device numbers.** Run `scripts/bench-device.sh` on real phones (GPU backend, two clients sharing one model) and record the results in [development.md](development.md#measuring-on-a-device). Only emulator CPU numbers exist so far.
5. **Two apps indexing at the same time, end to end.** Per-app turns of background requests (`PriorityGate`) are covered by unit tests only. An end-to-end check needs a second client with its own package name (for example a small test client app in this repository) indexing next to Nunsori, and the log showing their requests alternate.
